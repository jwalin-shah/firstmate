# Proof enforcement

This document is the authoritative human-readable contract for development-contract write gating.
`bin/fm-proof.sh` is the single owner of the ordered ledger, evidence rules, and the `implement_ready` bit.
`bin/fm-proof-pretool-check.sh` is the stable PreToolUse transport and harness output renderer.
Tracked harness adapters forward write-shaped tool calls without re-implementing step order.

It sits beside the existing PreToolUse family:
the watcher-arm seatbelt (`docs/arm-pretool-check.md`), the cd-guard (`docs/cd-guard.md`), and the subagent guard (`docs/subagent-guard.md`).

## Purpose and boundary

ADR-004 and the living fundamentals document require:

```text
githits → axioms → tensor equation → pseudocode → proof → implement → P0 gate → executable invariant → axiom ingest → loop
```

Prose alone does not stop a worker from writing code early.
This gate refuses write-shaped tool calls while enforcement is active and any pre-implement step is incomplete.

The CLI records evidence; it does not run `githits` or query the axioms corpus for you.
Hooks only classify write shape and call `fm-proof.sh check-write`.

## Tensor equations

```text
∀ change C, ∀ write W targeting code under C:
  admitted(W, C) ⇔ enforce(C) = false
                 ∨ (ledger(C).pre_implement_complete ∧ current(evidence))

∀ step S_i in PRE = [githits, axioms, tensor_equation, pseudocode, proof]:
  complete(S_i) ⇒ (i = 0 ∨ complete(S_{i-1}))
  complete(S_i) ⇒ evidence(S_i) ≠ ∅

loop(C, counterexample) ⇒ ¬implement_ready(C) ∧ resume_at(tensor_equation)
```

`proof` may be a formal artifact path or an explicit `--gap` with rationale.
A gap completes the proof stage; it does not waive the later executable-invariant step.

## Enforcement activation

Enforcement is active when any of the following hold in the target repo:

1. `FM_PROOF_ENFORCE=1` (or `true`/`yes`/`on`) in the environment.
2. A marker file at `.proof/enforce`.
3. An open ledger with `"enforce": true` (the default for `fm-proof.sh init`).

When inactive, `check-write` allows and hooks are silent.

## Ledger location and steps

- Path: `<repo>/.proof/ledger.json` (atomic replace).
- Pre-implement (block writes until all complete): `githits`, `axioms`, `tensor_equation`, `pseudocode`, `proof`.
- Post-implement (recorded, not required for write admission): `p0_gate`, `executable_invariant`, `axiom_ingest`.

### Evidence shapes

| Step | Required evidence |
| --- | --- |
| `githits` | `--query` and/or `--evidence` |
| `axioms` | `--evidence` and/or `--ids` |
| `tensor_equation` | `--evidence` containing `∀` / `forall` |
| `pseudocode` | `--evidence` and/or `--path` |
| `proof` | `--path`/`--evidence`, or `--gap REASON` |
| `p0_gate` | `--evidence`, `--command`, and/or `--exit-code` (via `gate`) |
| `executable_invariant` | `--evidence`, `--path`, and/or `--command` |
| `axiom_ingest` | `--evidence` and/or `--path` |

## CLI

```sh
bin/fm-proof.sh init <id> [--summary TEXT] [--enforce|--no-enforce] [--force]
bin/fm-proof.sh record <step> --evidence TEXT [--path FILE] [--query TEXT] [--gap REASON] [--ids ID,ID] [--command TEXT] [--exit-code N]
bin/fm-proof.sh status [--json]
bin/fm-proof.sh check-write [--json]    # exit 0 allow, exit 2 deny
bin/fm-proof.sh gate [--command TEXT] [--exit-code N] [--evidence TEXT]
bin/fm-proof.sh invariant --evidence TEXT [--path FILE] [--command TEXT]
bin/fm-proof.sh ingest --evidence TEXT [--path FILE]
bin/fm-proof.sh loop --counterexample TEXT
bin/fm-proof.sh path
bin/fm-proof.sh clear --force
```

`loop` keeps `githits` and `axioms`, clears from `tensor_equation` through the end, stores the counterexample, and clears `implement_ready`.

## Hook transport

`bin/fm-proof-pretool-check.sh` denies when:

- the tool name is write-shaped (`write`, `edit`, `multiedit`, `apply_patch`, …), or
- bash looks write-shaped (redirection, `tee`, `cp`/`mv`/`rm`, `sed -i`, …),

and `fm-proof.sh check-write` returns 2.

It always allows:

- non-write tools and read-only bash,
- the proof CLI itself (`fm-proof.sh`, `fm-proof-pretool-check.sh`),
- writes under `.proof/` and to `docs/proof-enforcement.md`.

Exit/output contract matches the other PreToolUse seatbelts:

- ALLOW: exit 0, no output.
- DENY: exit 2, Claude-shaped deny object on stderr, Grok-shaped deny on stdout unless `--claude`.
- FAIL OPEN: empty/malformed stdin, missing `jq` for stdin transport, or missing proof CLI.

## Threat model and non-goals

Threat model is agent mistake, not a hostile bypass.
Obfuscated bash that hides writes can miss the classifier; that is accepted.
Enforcement does not replace code review, no-mistakes, or formal verification.
Scout tasks that only write `data/<id>/report.md` outside an enforced project tree are unaffected unless that tree opts in.

## Operator workflow

```sh
# In the project worktree
bin/fm-proof.sh init "$TASK_ID" --summary "short intent"
bin/fm-proof.sh record githits --query "<problem>" --evidence "what prior art showed"
bin/fm-proof.sh record axioms --evidence "which invariants apply" --ids AX-...
bin/fm-proof.sh record tensor_equation --evidence "∀k,t: ..."
bin/fm-proof.sh record pseudocode --path path/to/design.md --evidence "summary"
bin/fm-proof.sh record proof --gap "executable tests only"   # or --path to Dafny/Lean
# writes now admitted
# ... implement ...
bin/fm-proof.sh gate --command 'bin/fm-lint.sh'
bin/fm-proof.sh invariant --evidence "tests/fm-proof.test.sh covers ordered record + deny"
bin/fm-proof.sh ingest --evidence "no new axiom this change"
```

If a gate or invariant fails:

```sh
bin/fm-proof.sh loop --counterexample "what broke"
# re-record tensor_equation → ... before writing again
```
